# E1-2 🎯 농구 퀴즈 게임 [컴퓨터에게 명령 내리는 말(파이썬) 처음 배우기]

## 1. 프로젝트 개요

#### 동작하는 퀴즈 게임 만들기

- 프로그램 실행 시 메뉴에서 번호를 선택하면, 퀴즈 풀기/퀴즈 추가/퀴즈 목록/점수 확인/퀴즈 삭제/점수 기록/종료 화면이 출력된다.

- 퀴즈 풀기, 퀴즈 추가, 퀴즈 목록, 점수 확인, 퀴즈 삭제, 점수 기록, 종료 기능이 동작한다.

- 본인이 선택한 주제의 퀴즈가 5개 이상 포함되어 있다.

- 프로그램을 종료하고 다시 실행해도 추가한 퀴즈와 최고 점수가 유지된다.(파일 저장)

## 2. 퀴즈 주제 선정 이유

- 농구를 좋아하기 때문에 농구를 퀴즈 주제로 선택했습니다.

- 관심 있는 분야의 퀴즈를 만들면 더 재미있게 개발할 수 있고, 농구에 대해 이미 알고 있는 지식을 활용해서 퀴즈 문제를 쉽게 만들 수 있습니다.

              "answer": 1,
              "hint": "NBA 경기에서 코트에 나가는 선수 수입니다."

      ],
      "best_score": 80,
      "best_record": {
          "correct": 4,
          "total": 5
      },
      "history": [
          {
            "date": "2026-11-10T22:01:18.202642",
            "question": "농구에서 파울이 6번이 되면?",
            "user_answer": 3,
            "correct_answer": 3,

            "score": 10

  | `history[].user_answer` | 정수 | 유저가 제출한 정답 |
  | `history[].correct_answer` | 정수 | 문제의 정답 |
  | `history[].is_correct` | 불린 | 정답 유무 |

## 1. 파이썬 기초

#### 1) 변수가 무엇이고, 왜 사용하는가?

  - 변수란: 컴퓨터의 메모리에 저장하는 상자로 값을 담아둔다.
    
  - 왜 사용하는가?
    - 값을 기억하고 재사용하기 위해서 (재사용성): 컴퓨터는 계산을 하고 나면 결과를 금방 잊어버립니다. 계산한 결과나 중요한 데이터를 메모리에 저장(기억)해 두고, 필요할 때마다 몇 번이고 다시 불러다 쓰기 위해 변수가 필요합니다.
    - 코드의 가독성을 높이기 위해서 (가독성): 코드 안에 의미를 알 수 없는 숫자나 문자(예: 3.141592, 1000000)가 그대로 적혀 있으면 나중에 코드를 읽거나 수정할 때 무슨 뜻인지 알기 어렵습니다. 변수에 의미 있는 이름을 붙여주면 코드가 어떤 일을 하는지 한눈에 알아보기 쉬워집니다.
    - 값이 바뀔 때 쉽게 관리하기 위해서 (유지보수): 프로그램을 만들다 보면 데이터가 계속 바뀝니다. 예를 들어 게임에서 유저의 점수나 레벨, 쇼핑몰 장바구니의 총 금액 등은 수시로 변합니다. 변수를 사용하면 값 자체를 하드코딩(고정)하지 않고, 변수 안의 내용물만 쏙 바꿔 끼울 수 있어 프로그램 수정이 매우 편리해집니다.
    - 프로그램에 '동작'을 주기 위해서 (동적 처리): 프로그램은 사용자 입력이나 상황에 따라 결과가 달라져야 합니다. 예를 들어 사용자가 입력한 나이에 따라 다른 메시지를 출력하거나, 쇼핑몰에서 장바구니에 담는 물건에 따라 총합이 계산되려면 데이터를 담고 바꿀 수 있는 그릇(변수)이 필수적입니다.

#### 2) 기본적인 자료

| 데이터 타입 | 이름 | 설명 | 예시 |
| :---: | :--- | :--- | :--- |

#### 3) 조건문

| 키워드 | 역할 및 설명 | 필수 여부 | 코드 예시 |
| :---: | :--- | :---: | :--- |
| **`if`** | 가장 먼저 실행되는 **최초의 조건**을 검사합니다. 참이면 해당 블록을 실행합니다. | **필수** | `if score >= 90:` |
| **`elif`** | 앞선 조건들이 모두 거짓이고, **새로운 조건이 참인지** 검사합니다. (여러 개 사용 가능) | 선택 | `elif score >= 80:` |
| **`else`** | 위의 **모든 조건이 거짓일 때** 무조건 실행되는 마지막 블록입니다. | 선택 | `else:` |

```python
score = 85

if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "F"

print(f"당신의 학점은 {grade}입니다.")  # 출력 결과: 당신의 학점은 B입니다.
```

#### 4) 반복문

| 구분 | `for`문 | `while`문 |
| :---: | :--- | :--- |
| **주요 목적** | **횟수**가 정해져 있거나, 데이터의 **처음부터 끝까지 순회**할 때 | 특정 **조건이 참(True)인 동안** 계속 반복할 때 |
| **반복 종료 시점** | 순회할 데이터나 범위가 끝났을 때 | 조건식의 결과가 거짓(False)이 되었을 때 |
| **주 사용 사례** | 리스트 요소 하나씩 꺼내기, 정해진 횟수만큼 반복 | 특정 상태가 될 때까지(예: 사용자 입력 대기, 게임 루프) |

```python
# 0부터 4까지 총 5번 반복
for i in range(5):
    print(f"현재 숫자: {i}")

# 리스트 요소 순회
fruits = ["apple", "banana", "cherry"]
for fruit in fruits:
    print(fruit)

# 카운트가 0보다 큰 동안 반복
count = 3
while count > 0:
    print(f"남은 시간: {count}")
    count -= 1  # 조건을 끝내기 위한 장치 필수!

print("발사!")
```

#### 5) 함수, 매개변수, 반환값

| 개념 / 용어 | 역할 및 설명 | 코드 예시 |
| :---: | :--- | :--- |
| **함수 정의 (`def`)** | 새로운 함수를 만들 때 사용하는 키워드입니다. 콜론(`:`)과 들여쓰기가 필수입니다. | `def add(a, b):` |
| **매개변수 (Parameter)** | 함수가 실행될 때 외부에서 **값을 전달받는 변수(입구)**입니다. | `def greet(name):` 의 `name` |
| **반환값 (`return`)** | 함수의 실행 결과를 함수 바깥으로 **내보내는 값(출구)**입니다. | `return result` |

```python
# 1. 함수 정의 (매개변수 a, b를 받아 더한 뒤 반환)
def add_numbers(a, b):
    result = a + b
    return result  # 반환값, return이 되면 함수는 종료

# 2. 함수 호출 (인수 3과 5를 전달)
sum_result = add_numbers(3, 5)  # 매개변수는 변수, 인는 그 값임

print(f"더하기 결과: {sum_result}")  # 출력 결과: 더하기 결과: 8
```

## 2. 클래스와 객체

#### 클래스가 무엇이고, 왜 사용하는가?

  - 클래스란?: **"객체를 만들어내기 위한 설계도(Blueprint)"**입니다. 연관된 데이터(변수)와 기능(함수)들을 하나로 묶어서 관리할 수 있게 해주는 객체지향 프로그래밍(OOP) 도구입니다.
  
  - 왜 사용하는가?:
    - 데이터와 기능을 하나로 묶기 위해 (캡슐화): 관련된 변수들과 함수들이 여기저기 흩어져 있으면 코드가 복잡해집니다. 클래스를 쓰면 관련된 데이터와 기능을 하나의 상자(객체) 안에 깔끔하게 모아둘 수 있습니다.
    - 비슷한 구조의 객체를 대량으로 찍어내기 위해 (재사용성): 게임 캐릭터, 쇼핑몰 상품, 회원 정보처럼 구조는 같지만 데이터만 다른 객체가 수십, 수백 개 필요할 때 클래스라는 설계도 하나만 있으면 코드를 복사·붙여넣기 할 필요 없이 손쉽게 생성할 수 있습니다.
    - 코드의 유지보수와 확장성 향상: 프로그램 규모가 커져도 수정할 곳이 명확해집니다. 특정 기능이나 데이터를 수정할 때 해당 클래스 내부만 고치면 되므로 관리하기가 훨씬 수월해집니다.

| 개념 / 용어 | 역할 및 설명 | 코드 예시 |
| :---: | :--- | :--- |
| **클래스 (Class)** | 객체를 생성하기 위한 **설계도**(틀)입니다. | `class Car:` |
| **인스턴스 (Instance)** | 설계도를 바탕으로 실제로 만들어진 **구체적인 객체**입니다. | `my_car = Car()` |
| **생성자 (`__init__`)** | 인스턴스가 생성될 때 초기 속성(데이터)을 설정해주는 **특별한 함수**입니다. | `def __init__(self, name):` |
| **`self`** | 생성된 **인스턴스 자기 자신**을 가리키는 약속된 변수입니다. | `self.name = name` |

```python
# 1. 클래스 정의 (설계도)
class Car:
    # 생성자: 차를 만들 때 이름과 색상을 지정합니다.
    def __init__(self, name, color):
        self.name = name       # 속성 (데이터)
        self.color = color     # 속성 (데이터)
        self.speed = 0         # 기본 속도 (초기값)

    # 메서드 (함수/기능)
    def accelerate(self, value):
        self.speed += value
        print(f"{self.name}의 속도가 {self.speed}km/h로 증가했습니다.")

# 2. 인스턴스 생성 (설계도로 실제 차 만들기)
car1 = Car("소나타", "흰색")
car2 = Car("벤츠", "검은색")

# 3. 메서드 호출 (기능 사용)
car1.accelerate(30)  # 출력 결과: 소나타의 속도가 30km/h로 증가했습니다.
car2.accelerate(50)  # 출력 결과: 벤츠의 속도가 50km/h로 증가했습니다.
```

## 3. 파일 입출력

#### 1) 파일을 열고, 읽고, 쓰기

파일을 열 때(`open()`) 어떤 목적로 열 것인지 **모드(Mode)**를 지정해야 합니다.

| 모드 | 기호 | 설명 | 파일이 없을 때 |
| :---: | :---: | :--- | :--- |
| **읽기 모드** | `"r"` | 파일을 읽기 전용으로 엽니다. (기본값) | 에러 발생 (`FileNotFoundError`) |
| **쓰기 모드** | `"w"` | 파일에 새로 내용을 씁니다. **(기존 내용이 덮어씌워짐)** | 새로 파일을 생성함 |
| **추가 모드** | `"a"` | 기존 파일의 **맨 뒤에 새로운 내용을 이어 붙입니다.** | 새로 파일을 생성함 |

```python
# 1. 파일 열기 (쓰기 모드): 해당 파일을 객체로 가져오는 것
file = open("test.txt", "w", encoding="utf-8")

# 2. 파일에 내용 쓰기: 해당 파일에 문자열 등의 값에 쓰기-읽기-추가 함
file.write("안녕하세요, 파이썬 파일 입출력입니다!")

# 3. 파일 닫기 (매우 중요!)
file.close()
```
실전 사용 tip
```
# with 블록이 끝나면 자동으로 file.close()가 실행됩니다.
with open("hello.txt", "w", encoding="utf-8") as f:

    f.write("두 번째 줄입니다.")

# 파일 전체 내용을 읽어서 출력하기
with open("hello.txt", "r", encoding="utf-8") as f:
    content = f.read()
    print(content)

# 기존 내용 뒤에 새로운 내용을 추가합니다.
with open("hello.txt", "a", encoding="utf-8") as f:
    f.write("\n세 번째 줄을 이어 씁니다.")
```

#### 2) JSON?

  - JSON (JavaScript Object Notation)이란?

JSON은 **"JavaScript Object Notation"**의 약자로, **데이터를 저장하고 교환하기 위해 만들어진 가볍고 읽기 쉬운 텍스트 기반의 형식**입니다. 

사람이 읽기 편하고 컴퓨터가 파싱(분석)하기도 쉬워, 오늘날 웹 개발과 데이터 통신에서 가장 널리 쓰이는 표준 포맷입니다.

  - JSON은 기본적으로 **키(Key)와 값(Value)의 쌍**으로 이루어진 데이터 구조입니다.

| 구분 | 기호 및 형태 | 설명 | 예시 |
| :---: | :---: | :--- | :--- |
| **객체 (Object)** | `{ }` (중괄호) | 키(Key)와 값(Value)의 쌍으로 이루어진 데이터 모음입니다. | `{"name": "홍길동", "age": 25}` |
| **배열 (Array)** | `[ ]` (대괄호) | 순서가 있는 값들의 목록(리스트)입니다. | `["apple", "banana", "cherry"]` |
| **키 (Key)** | 큰따옴표 (`" "`) | 반드시 **큰따옴표**로 감싸야 합니다. (작은따옴표 불가) | `"username"` |
| **값 (Value)** | 문자열, 숫자, 불리언 등 | 문자열은 `" "`, 숫자는 그냥, 불리언은 `true`/`false` | `"kim"`, `100`, `true` |

#### 3) try/except를 사용 오류(예외) 처리

  - 예외 처리 (`try / except`)

프로그램을 만들다 보면 0으로 나누기, 존재하지 않는 파일 열기, 숫자를 입력해야 하는데 문자를 입력하는 등 다양한 **오류(Error / Exception)**가 발생합니다. 

예외 처리를 사용하면 프로그램이 강제로 종료(크래시)되는 것을 막고, **오류가 발생했을 때 우아하게 대처(복구)**할 수 있습니다.


| 키워드 | 역할 및 설명 |
| :---: | :--- |
| **`try`** | 오류가 발생할 가능성이 있는 코드를 작성하는 블록입니다. |
| **`except`** | `try` 블록 안에서 오류가 발생했을 때 실행될 코드를 작성하는 블록입니다. |
| **`else`** | 오류가 발생하지 않고 **성공적으로 실행되었을 때** 실행되는 블록입니다. (선택) |
| **`finally`** | 오류 발생 여부와 상관없이 **무조건 마지막에 항상 실행**되는 블록입니다. (선택) |


```python
# 기본 예제 (숫자 0으로 나누기 오류 처리)
try:
    # 0으로 나누는 시도 (ZeroDivisionError 발생)
    result = 10 / 0
except ZeroDivisionError:
    print("0으로 나눌 수 없습니다!")

print("프로그램이 강제 종료되지 않고 여기까지 정상 실행됩니다.")

# 다양한 오류 잡기 및 else, finally 활용
try:
    age = int(input("나이를 입력하세요: "))
except ValueError:
    # 숫자가 아닌 문자를 입력했을 때
    print("유효한 숫자를 입력해주세요!")
else:
    # 오류가 없을 때 실행
    print(f"입력하신 나이는 {age}살입니다.")
finally:
    # 성공하든 실패하든 무조건 실행되는 마무리 작업
    print("프로그램을 종료합니다.")
```

## 4. Git 기초

#### 1) Git이 무엇이고, 왜 필요한가?

  - Git이란? (Definition)
Git은 프로그램 소스 코드의 **변경 이력을 추적하고 관리**할 수 있는 분산 버전 관리 시스템입니다. 
여러 사람이 함께 코드를 개발할 때 누가, 언제, 어떤 코드를 수정했는지 기록해주고, 이전 버전으로 되돌릴 수 있게 도와줍니다.

| 개념 / 용어 | 역할 및 설명 |
| :---: | :--- |
| **버전 관리 (Version Control)** | 파일의 수정 내역을 단계별(버전별)로 기록하여 언제든 과거 상태로 되돌릴 수 있는 기능입니다. |
| **분산형 (Distributed)** | 중앙 서버뿐만 아니라 개발자 개인 컴퓨터(로컬)에도 전체 히스토리가 통째로 복사되어 안전하게 관리됩니다. |
| **저장소 (Repository, 깃허브)** | 프로젝트 파일과 변경 이력(Commit)들이 모여 있는 저장 공간입니다. |

  - Git을 왜 사용할까요? (사용하는 이유)
    - **과거 버전으로 되돌리기**: 코드를 수정하다가 에러가 나거나 코드가 망가졌을 때, 과거에 잘 작동하던 시점(Commit)으로 언제든지 안전하게 되돌릴 수 있습니다. (더 이상 `final_final_real_final.py` 같은 이름으로 파일을 여러 개 만들 필요가 없습니다!)
    - **백업과 협업 (Collaboration)**: 내 컴퓨터가 고장 나거나 데이터를 잃어버려도 원격 저장소(GitHub 등)에 코드를 백업해 둘 수 있습니다. 또한, 여러 명의 개발자가 동시에 같은 프로젝트를 수정해도 충돌 없이 코드를 합칠 수 있습니다.
    - **변경 이력 추적 (History)**: "누가", "언제", "왜" 코드를 수정했는지 기록이 고스란히 남기 때문에 버그가 발생했을 때 원인을 쉽게 찾아낼 수 있습니다.
   
#### 2) 필수 Git 명령어 7가지 정리

Git을 사용할 때 가장 빈번하게 쓰는 핵심 명령어들의 역할과 설명입니다.

| 명령어 | 이름 및 역할 | 설명 | 대표적인 사용 예시 |
| :---: | :--- | :--- | :--- |
| **`git init`** | **초기화** | 내 컴퓨터의 로컬 폴더를 Git이 관리하는 **버전 관리 저장소(Repository)로 지정**합니다. | `git init` |
| **`git clone`** | **복제** | 원격 저장소(GitHub 등)에 있는 프로젝트를 **내 컴퓨터로 통째로 다운로드**합니다. | `git clone [주소]` |
| **`git add`** | **스테이지 등록** | 수정하거나 새로 만든 파일들을 **다음 버전(Commit)에 포함시키기 위해 대기**시키는 공간으로 보냅니다. | `git add .` |
| **`git commit`** | **버전 생성** | 현재 대기 중인(Add된) 파일들의 상태를 모아 **하나의 의미 있는 버전(이력)으로 확정**합니다. | `git commit -m "메시지"` |
| **`git push`** | **업로드** | 내 컴퓨터(로컬)에서 작업하고 Commit한 내용들을 **원격 저장소(GitHub)로 업로드**합니다. | `git push origin main` |
| **`git pull`** | **다운로드 & 병합** | 원격 저장소(GitHub)에 있는 최신 변경 내용을 **내 컴퓨터로 가져와서 현재 코드와 합칩니다.** | `git pull origin main` |
| **`git checkout`** | **가지치기 / 이동** | 다른 브랜치로 이동하거나, 과거의 특정 커밋 상태로 잠시 이동(확인)할 때 사용합니다. | `git checkout 브랜치이름` |

#### 3) 브랜치 생성 및 병합

  - 브랜치란? (Definition)
**브랜치(Branch)**는 독립적으로 코드를 수정할 수 있도록 만들어주는 **"나만의 작업 공간(가지)"**입니다. 
기존의 메인 코드(`main` 또는 `master`)를 망가뜨리지 않고, 새로운 기능을 추가하거나 버그를 고칠 때 안전하게 실험할 수 있게 해줍니다.

| 명령어 / 개념 | 역할 및 설명 | 대표적인 사용 예시 |
| :---: | :--- | :--- |
| **`git branch`** | 현재 생성된 브랜치 목록을 확인하고, 어떤 브랜치에 있는지 보여줍니다. | `git branch` |
| **`git switch`** (또는 `checkout`) | 작업할 브랜치를 **다른 브랜치로 전환**합니다. | `git switch 기능이름`<br>`git checkout 기능이름` |
| **`git switch -c`** (또는 `check -b`) | 새로운 브랜치를 **동시에 생성하고 그쪽으로 이동**합니다. | `git switch -c feature/login` (c = create, b = branch|
| **`git merge`** | 다른 브랜치의 작업 내용을 **현재 내가 있는 브랜치로 합칩니다.** | `git merge feature/login` |
| **`git branch -d`** | 더 이상 필요 없는 **브랜치를 삭제**합니다. | `git branch -d feature/login` |


```bash
# 1. feature라는 새로운 브랜치를 만들고 이동합니다.
git switch -c feature/login
git add .
git commit -m "로그인 기능 UI 구현 완료"

# 2. 메인 브랜치로 이동
git switch main

# 3. feature 브랜치의 내용을 main에 병합
git merge feature/login

# 4. 원격 저장소의 main 브랜치에도 최종 반영하기
git push origin main
```

# E1-2 🎯 농구 퀴즈 게임 [프로젝트를 만드는 과정은 어떤 사고 단계를 거치나?]

## 1단계: 설계 (머릿속으로 그림 그리기)

객체지향 패러다임: 코드를 치기 전, 가장 먼저 **"이 프로그램에는 어떤 '물건(클래스 / 객체)'이 필요하고, 그 안에는 어떤 '자료(데이터 / 속성)'와 어떤 '동작(기능 / 메서드)'을 해야 하는가?"**를 정의합니다.

#### 튜터의 팁 🌟
처음에는 **"최소 단위"**부터 생각하세요. 이 프로젝트에서 가장 작은 단위는 '퀴즈 문제 하나'입니다.
문제 하나를 표현하기 위해 뭐가 필요할지 고민하다 보면 자연스럽게 Quiz 클래스가 만들어지고, 그 문제들을 관리할 곳을 찾다 보면 QuizGame 클래스가 만들어지게 됩니다.

#### 1) 요구사항을 '평범한 문장'으로 적어보기

가장 먼저 할 일은 코드가 아니라, 우리말(나만의 도구)로 프로그램이 어떻게 돌아갈지 아주 자세히 적는 것(완성작을 구체화 하기)입니다.

"사용자는 농구 문제를 본다. 문제에는 질문, 4개의 선택지, 정답 번호가 있다. 사용자가 번호를 입력하면 정답인지 확인한다. 게임 관리자는 여러 개의 문제들을 가지고 있고, 최고 점수를 저장하거나 불러온다."

#### 2) 명사(Noun)와 동사(Verb) 찾기
위에서 쓴 문장에서 명사와 동사를 따로 골라냅니다. 이것이 클래스의 뼈대가 됩니다.

명사 (데이터 / 속성): 농구 문제, 질문, 선택지, 정답 번호, 게임 관리자, 문제 리스트, 최고 점수.
동사 (기능 / 메서드): 문제를 보여준다, 정답인지 확인한다, 저장한다, 불러온다.

#### 3) 명사와 동사를 '상자(클래스)'에 나눠 담기
이제 골라낸 명사와 동사 중 서로 관련 있는 것끼리 묶어봅니다. 이때 **"누구의 책임인가?"**를 생각하는 것이 핵심입니다.


- 상자 A: 퀴즈 (Quiz)

  - 명사(데이터): 질문, 선택지, 정답 번호, 힌트

  - 동사(기능): 문제 보여주기(show), 정답 확인하기(check_answer)

  - 이유: 질문과 정답은 퀴즈의 핵심 정보이고, 정답을 확인하는 일은 퀴즈 스스로가 가장 잘 알기 때문입니다.


- 상자 B: 퀴즈 게임 관리자 (QuizGame)

  - 명사(데이터): 퀴즈 객체들의 리스트, 최고 점수, 파일 경로

  - 동사(기능): 게임 시작하기(run), 데이터 로드(load_state), 데이터 저장(save_state)

  - 이유: 개별 퀴즈는 전체 점수가 몇 점인지, 파일이 어디에 저장되는지 알 필요가 없습니다. 전체를 총괄하는 관리자가 필요합니다.

#### 4) 클래스 간의 관계 정의하기 (누가 누구를 사용하는가?)
상자를 만들었으면 이제 어떻게 연결될지 정합니다.

QuizGame 관리자가 Quiz 상자 여러 개를 리스트(self.quizzes)로 들고 있습니다.

관리자가 "자, 1번 문제 나와!"라고 하면 Quiz 객체가 show() 메서드로 자기 내용을 화면에 뿌립니다.

사용자가 답을 입력하면 관리자가 Quiz 객체에게 "이 답(n)이 맞니?"라고 물어보고(check_answer(n)), 그 결과를 받아 점수를 올립니다.

#### 💡 요약하자면, 클래스 설계는 '역할 분담'입니다.
|단계|행동|결과|
|:---:|:---|:---:|
|1단계|문장 만들기	프로그램의 흐름을 글로 쓴다.|시나리오 완성|
|2단계|단어 추출	명사와 동사를 골라낸다.|재료 준비|
|3단계|그룹화	관련 있는 것끼리 묶어 클래스 이름을 붙인다.|클래스 도출|
|4단계|속성/메서드	명사는 변수로, 동사는 함수로 만든다.|코드 설계|

#### 튜터의 팁 🌟
처음에는 **"최소 단위"**부터 생각하세요. 이 프로젝트에서 가장 작은 단위는 '퀴즈 문제 하나'입니다. 문제 하나를 표현하기 위해 뭐가 필요할지 고민하다 보면 자연스럽게 Quiz 클래스가 만들어지고, 그 문제들을 관리할 곳을 찾다 보면 QuizGame 클래스가 만들어지게 됩니다.

## 2단계: 최소 기능 제품(MVP) 만들기
처음부터 '퀴즈 삭제'나 '히스토리 보기' 같은 복잡한 기능을 만들지 않습니다. **"퀴즈 하나가 화면에 나오고 정답을 맞힐 수 있는가?"**에만 집중합니다.

quiz.py를 먼저 만듭니다. (가장 작은 단위인 '문제' 정의)

quiz_game.py에서 퀴즈 하나를 리스트에 넣고, input()으로 답을 받아 if문으로 확인하는 아주 간단한 코드부터 시작합니다.

막막함을 느끼는 것은 아주 정상입니다! 이 막막함을 깨는 비결은 **"코드를 한 줄씩 쓰면서 바로바로 실행해 보는 것"**입니다.

전문 개발자가 MVP를 만들 때 머릿속으로 하는 **'혼잣말(사고 과정)'**을 그대로 따라가 봅시다.

#### 1) `quiz.py` - "붕어빵 틀(클래스)부터 만들자"

**사고 과정:**
1. "일단 퀴즈 하나에 뭐가 들어가지? 질문, 보기 4개, 정답 번호가 필요해."
2. "이걸 저장할 `__init__`을 만들자."
3. "화면에 보여주는 기능도 퀴즈가 직접 하면 편하겠지? `show` 메서드를 만들자."

**실제 작성 코드 (아주 단순하게):**
```python
# quiz.py
class Quiz:
    def __init__(self, question, choices, answer):
        self.question = question
        self.choices = choices
        self.answer = answer

    def show(self):
        print(f"\n문제: {self.question}")
        for i, choice in enumerate(self.choices, 1):
            print(f"{i}. {choice}")
```

**💡 여기서 멈추고 테스트!**
파일 맨 밑에 아래 코드를 넣고 실행해 봅니다. "오! 화면에 잘 나오네?" 확인하는 게 중요합니다.
```python
# 테스트용 (확인 후 삭제)
q = Quiz("농구 선수는 몇 명?", ["4", "5", "6", "7"], 2)
q.show()

# bash에서 실행 예) leonaryedo6914....:....basketball-quiz$ puthon3 quiz.py
```

#### 2) `quiz_game.py` - "틀을 가져와서 실제로 써보자"

**사고 과정:**
1. "이제 `quiz.py`에 만든 틀을 불러오자 (`import`)."
2. "문제를 여러 개 담을 리스트를 만들고, 퀴즈 객체를 몇 개 넣어보자."
3. "반복문(`for`)을 돌려서 문제를 하나씩 꺼내고, 사용자한테 답을 물어보자."

**실제 작성 코드 (MVP 버전):**
```python
# quiz_game.py
from quiz import Quiz

# 1. 데이터 준비 (아직 JSON 안 씀!)
q1 = Quiz("농구 선수는 몇 명?", ["4명", "5명", "6명", "7명"], 2)
q2 = Quiz("3점슛 점수는?", ["1점", "2점", "3점", "4점"], 3)
quizzes = [q1, q2]

# 2. 게임 실행 루프
print("=== 농구 퀴즈 시작 ===")
for q in quizzes:
    q.show()  # 퀴즈가 스스로를 보여줌
    user_input = input("정답 번호 입력: ")
    
    # 3. 정답 확인 (가장 단순한 방식)
    if int(user_input) == q.answer:
        print("정답입니다!")
    else:
        print(f"틀렸습니다. 정답은 {q.answer}번입니다.")
```

#### 3) "점수 기능을 추가해볼까?" (살 붙이기)

**사고 과정:**
1. "그냥 맞았다 틀렸다만 하니까 심심하네. 점수를 계산해볼까?"
2. "변수 `score`를 0으로 만들고, 맞힐 때마다 10점씩 더하자."

**수정 코드:**
```python
score = 0
for q in quizzes:
    # ... (위와 동일)
    if int(user_input) == q.answer:
        print("정답!")
        score += 10
    # ...
print(f"최종 점수: {score}점")
```

#### 💡 전문 개발자의 핵심 사고 방식 (Tip)

1.  **"완벽"보다 "작동"이 우선:** 처음부터 `state.json`을 연결하려고 하면 머리가 터집니다. 위 코드처럼 **변수에 직접 데이터를 넣어서(하드코딩)** 게임 로직이 돌아가는지부터 확인하세요.
2.  **3줄 쓰고 실행하기:** 코드를 많이 짜고 실행하면 어디서 틀렸는지 찾기 힘듭니다. `Quiz` 클래스 만들고 실행, `for`문 만들고 실행, 이렇게 자주 확인하세요.
3.  **메서드로 옮기기:** 위 `quiz_game.py`에서 `if int(user_input) == q.answer:` 부분이 좀 지저분해 보인다면, 그때 `quiz.py`로 가서 `check_answer` 메서드를 만드는 식으로 코드를 개선(리팩토링)합니다.

#### 다음 단계로 넘어가려면?
위의 MVP 코드가 에러 없이 잘 돌아간다면, 그때 비로소 **"이걸 어떻게 JSON 파일에 저장하고 불러오지?"**라는 고민을 시작하면 됩니다. 

## 3단계: 데이터의 영속성 (저장 기능)
프로그램을 껐다 켜도 데이터가 유지되어야 하므로, 이 시점에서 JSON 연동을 고민합니다.

MVP에서 3단계(저장 기능)로 넘어가는 과정은 **'귀찮음'과 '불편함'을 해결하려는 아주 자연스러운 흐름**에서 시작됩니다.

- 첫 번째 불편함: "데이터를 추가할 때마다 코드를 수정해야 해?"
MVP 단계에서는 `q1 = Quiz(...)`, `q2 = Quiz(...)` 처럼 코드 안에 직접 데이터를 넣었습니다(하드코딩).

  - **사고 과정:** "문제를 100개 넣고 싶은데, 코드 파일이 너무 길어지네? 문제 데이터랑 실행 코드는 따로 분리하고 싶어."
  - **해결책:** "데이터만 따로 모아둔 파일을 만들자! 파이썬의 **딕셔너리**랑 똑같이 생긴 **JSON** 형식이 딱이겠네."

- 두 번째 불편함: "내 최고 점수가 왜 자꾸 사라지지?"
게임을 열심히 해서 100점을 맞았는데, 프로그램을 껐다 켜니 다시 0점부터 시작합니다.

  - **사고 과정:** "변수 `high_score`는 프로그램이 종료되면 메모리에서 사라져. 컴퓨터를 꺼도 남아있는 '하드디스크(파일)'에 적어둬야겠어."
  - **해결책:** "프로그램이 **시작될 때** 파일을 읽어오고(`load`), **끝날 때** 파일에 저장하자(`save`)."

- 세 번째 불편함: "코드가 너무 지저분해지는데?"
파일을 읽고 쓰는 코드를 `for`문 옆에 막 적다 보니 코드가 복잡해집니다.

  - **사고 과정:** "파일을 열고, 닫고, JSON으로 변환하는 복잡한 과정은 따로 모아두고 싶어. 관리자(QuizGame)한테 이 일을 시키자."
  - **해결책:** `QuizGame` 클래스 안에 `load_state()`와 `save_state()`라는 전용 메서드를 만듭니다.

#### 🛠️ 코드가 변하는 자연스러운 모습


1. 데이터 설계: `state.json` 구조

단순한 리스트가 아니라, **최고 점수**와 **퀴즈 목록**을 모두 담을 수 있는 딕셔너리 구조로 설계합니다.

```json
{
    "high_score": 100,
    "quizzes": [
        {
            "question": "농구 선수는 한 팀에 몇 명일까요?",
            "choices": ["4명", "5명", "6명", "7명"],
            "answer": 2
        },
        {
            "question": "농구에서 3점슛은 몇 점일까요?",
            "choices": ["1점", "2점", "3점", "4점"],
            "answer": 3
        }
    ]
}
```

2. 구현: `QuizGame` 클래스 업데이트

메서드 이름을 기능을 더 잘 설명하는 `load_state`와 `save_state`로 변경합니다.

```python
import json
from quiz import Quiz

class QuizGame:
    def __init__(self, file_path="state.json"):
        self.file_path = file_path
        self.quizzes = []
        self.high_score = 0
        self.load_state()  # ❶ 시작할 때 파일에서 상태 불러오기

    def load_state(self):
        """파일에서 최고 점수와 퀴즈 목록을 읽어옵니다."""
        try:
            with open(self.file_path, "r", encoding="utf-8") as f:
                data = json.load(f)
                # 최고 점수 복구
                self.high_score = data.get("high_score", 0)
                # ❷ 딕셔너리 리스트를 Quiz 객체 리스트로 변환
                self.quizzes = [
                    Quiz(q["question"], q["choices"], q["answer"]) 
                    for q in data["quizzes"]
                ]
        except (FileNotFoundError, json.JSONDecodeError):
            print("기존 저장 데이터가 없습니다. 새로 시작합니다.")
            self.quizzes = []

    def save_state(self):
        """현재 게임 상태(최고 점수, 퀴즈)를 파일에 저장합니다."""
        # ❸ 저장할 수 있는 딕셔너리 형태로 변환
        data = {
            "high_score": self.high_score,
            "quizzes": [
                {
                    "question": q.question,
                    "choices": q.choices,
                    "answer": q.answer
                } for q in self.quizzes
            ]
        }
        with open(self.file_path, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=4)
```

2.  **탐색:** "파일에 저장해야지. 파이썬 딕셔너리랑 제일 비슷한 게 뭐지? 아, JSON!"
3.  **설계:** "언제 저장하고 불러올까? 시작할 때 `load`, 점수가 바뀌거나 끝날 때 `save`!"

## 4단계: 리팩토링 (코드 정리 및 모듈화)
기능을 하나씩 추가하다 보면 quiz_game.py 파일이 너무 길어집니다(예: 300줄 이상). 이때 개발자는 **"관심사의 분리(Separation of Concerns)"**를 시작합니다.

문제 관리 관련은 manage.py로.
실제 게임 플레이 로직은 play.py로.
기록 보기는 record.py로.
이렇게 나누면 나중에 '퀴즈 추가' 기능에 버그가 생겼을 때 manage.py만 확인하면 되니 유지보수가 엄청나게 쉬워집니다.
5단계: 예외 처리와 사용자 경험(UX) (방어적 코딩)
프로그램이 어느 정도 돌아가면, 사용자가 실수할 상황을 대비합니다.

"숫자를 넣어야 하는데 문자를 넣으면 어떡하지?" → try...except 추가.
"파일이 삭제되어 있으면?" → FileNotFoundError 처리.
"힌트가 없을 때 힌트 버튼을 누르면?" → 조건문 처리.
💡 개발자가 이 방식을 선택한 이유 (핵심 요약)
클래스를 쓴 이유: Quiz 클래스를 만들면, 퀴즈가 5개든 100개든 똑같은 규칙(메서드)을 적용할 수 있기 때문입니다. (재사용성)
JSON을 쓴 이유: 텍스트 파일보다 구조적이고, 파이썬의 딕셔너리와 모양이 거의 똑같아서 변환이 매우 쉽기 때문입니다.
파일을 쪼갠 이유(actions 폴더): 한 파일에 코드가 너무 많으면 나중에 내가 쓴 코드도 못 찾게 됩니다. "Divide and Conquer(분할 정복)" 전략입니다.
